# 方法论内容契约

## 方法卡

方法卡是默认注入层，顺序固定为：

```text
when -> why -> how -> philosophy -> boundary
```

字段是可选语义字段，不是表单。标题是唯一必填项；来源没有写出哲学基础或边界时，提炼者必须省略，不得为了格式编造。卡片应足以让模型判断是否适用，但不把大量案例塞进默认上下文。

`detail` 是第二层内容，存放更长的解释、推导、案例、反例和实践步骤。简单方法可以没有 detail；需要更多证据时由 `methodology_get(..., mode="detail")` 按需读取。完整原文留在不可变 source 中。

方法可以描述“怎样选择、评价或修订其他方法”，所以递归和环不需要特殊节点类型。递归深度和停止条件属于运行时，不把本体硬编码成上下级、道术或固定阶段。

## 关系

边只有两个端点、自然语言 `explanation`、可选 `detail`、来源和内部 `weight`。不设关系类型枚举；“组合、前置、冲突、验证、特化、反馈”等语义直接写进 explanation。复杂组合本身也是普通方法节点，允许关系形成环。

权重只用于排序和学习投影，不注入模型。边来源用于审计，避免把“为什么这样连接”与正文混在一起。人工边和 Agent 边通过 `authority` 分开，Agent 不能修改人工边；学习到的统计联想应写入 Agent 层。

## 治理字段

方法和边独立保留 `authority`、`scope`、`domains`/`project_ref`、`importance`、创建/更新时间、创建者和来源。它们帮助过滤和审计，不改变方法语义。Git blob revision 由服务内部计算，不作为模型字段。来源至少有类型、标题、作者、出版时间、URI、定位、摘录、抓取时间、内容哈希和原文；来源文件本身不可原地覆盖。

方法、边和来源的权威内容位于服务端 Git 仓库；SQLite 只保存当前投影、embedding 和运行时激活状态。恢复通过新的 Git restore commit 完成，模型侧 `audit` 读取 Git history。
